【先说结论】
  · 176 帧（每 1.5 秒回一帧）里除速度外还有 30+ 个字段，本工程已经把
    它们【全部解析出来】放在 Sources/App/GaugeExtras.swift，只是还没画到界面上。
    → 你看中哪个，直接取 GaugeExtras 的对应属性即可，不用再逆向协议。
  · 另有 160 / 208 / 192 等帧能拿设备信息、电池包详情、单体电压、DCDC，
    但这些帧需要额外主动请求 + 新解析器，属于「二期」。
  · 2026-11-20 定稿并已实现（GaugeExtrasState 数据契约 + 两个小组件）：
    小组件 1 = 速度主仪表：档位 / 电量 / AP / 限速 / 转向灯 / 双温度；
    小组件 2 = 车身状态地图：四轮胎压与刹车温度 / 四门 / 前后备箱 /
    盲区 / 灯光位 / 电池加热（图标化，颜色即状态）。
    未选字段：雨刷位（176 帧无数据）、导航转弯距离（协议无来源）。
  · 你之前定的是「小组件界面要纯粹，只显示速度」。所以建议【不要】往现有的
    纯速度小组件里塞字段，而是另开一屏 / 另一个小组件（见文末「接入方式」）。

【A. 176 帧 · 已解析，零成本可直接上界面】
--------------------------------------------------------------------------------
 标记：★ = 已在本工程 GaugeState 里；＋ = 本轮新增在 GaugeExtras 里
 频率：全部随 176 帧，约 1.5 秒一次，和小组件/实时活动同一条数据链。

 A1 状态 / 驾驶辅助（最推荐放车机的几项）
  ① ★ 档位 gearLabel            P / R / N / D / 0        head bit9..11
  ② ＋ 电量 batteryPercent       0~127 %                  head bit24..30
  ③ ★ 单位 unit                 KM/H 或 MPH              byte17 bit6
  ④ ＋ 转向灯 turnLabel          关闭/左转/右转/双闪        head bit12..13
     ＋ 左转 / 右转布尔           turnLeftActive / turnRightActive
  ⑤ ＋ AP 辅助驾驶 autoPilotLabel  - / AP                   head bit14..15
  ⑥ ＋ 融合限速 speedLimitKmh     0/5/10...155 km/h         byte31~32 bit7..11
                                  （仅 R/N/D 挡有效，P 挡为 0）
  ⑦ ＋ 手扶方向盘提醒 handsOn    提示 / 正常                byte17 bit7
  ⑧ ＋ 盲区预警 blindSpotLabels  左/右：无/近距/中距/危险    byte31~32 bit12..15
  ⑨ ＋ 灯光位 lightHex           0xNN                     head bit20..23 / bit31 / byte4

 A2 车身 / 车门
  ⑩ ＋ 四门开关 openDoors        左前/右前/左后/右后        head bit16..19
  ⑪ ＋ 前备箱 frunkOpen          开 / 关                    LE32(4) bit1
  ⑫ ＋ 后备箱 trunkOpen          开 / 关                    LE32(4) bit5
  ⑬ ＋ 运动模式 sport            开 / 关                    LE32(4) bit3
  ⑭ ＋ 屏幕常亮 keepScreenOn     是 / 否                    LE32(4) bit0
  ⑮ ＋ 画面比例 aspect           0 / 1                      LE32(4) bit2

 A3 电池 / 续航 / 里程
  ⑯ ＋ 剩余续航 remainRangeKm    0~1647 km                  LE32(28) bit12..21 ×1.61
  ⑰ ＋ 总里程 odometerKm         0.1 km 精度                LE32(4) bit6..31 ÷10
  ⑱ ＋ 单体电压 cellVoltageV     0~8.19 V                   LE32(28) bit0..11 ×0.002
  ⑲ ＋ 电池温度 batteryTempC     ℃                          LE32(28) bit22..30 ×0.5−40
  ⑳ ★ 电池加热 batteryHeat      关闭/加热/预热/保温         byte17 bit4..5
     ＋ 同上的中文标签 batteryHeatLabel
  ㉑ ＋ 海拔 altitudeM            有符号 14 bit，米           byte15~17 bit6..19

 A4 轮胎 / 制动
  ㉒ ★ 四轮胎压 tirePressures     Bar                        byte8..11 ×0.025
     ＋ 同名带单位数组 tirePressuresBar（左前/右前/左后/右后）
  ㉓ ＋ 四轮刹车温度 brakeTempsC  ℃                          LE32(18) 10bit×3 + byte22
  ㉔ ＋ 加速踏板 accelPedalPercent 0~100 %                   LE32(12) bit0..7
  ㉕ ＋ 前电机功率 frontPowerKW   kW（可为负＝回收）          LE32(12) bit19..29 有符号÷2
  ㉖ ＋ 后电机功率 rearPowerKW    kW                          LE32(12) bit8..18 有符号÷2
  ㉗ ＋ 合计功率 totalPowerKW     kW                          前 + 后

 A5 空调 / 环境
  ㉘ ＋ 环境温度 ambientTempC     ℃                          byte27 ×0.5−40
  ㉙ ＋ 座舱温度 cabinTempC       ℃                          LE32(23) bit21..31 ×0.1−40
  ㉚ ＋ 鼓风机转速 blowerRPM      RPM                        LE32(23) bit0..9 ×5
  ㉛ ＋ 蒸发器功率 evapWatts      W                          LE32(23) bit10..20 ×5

 A6 由速度派生的展示（不需要新字段）
  ㉜ ★ 速度环占比 speedRingPercent  0~100 %               speedRaw/120
  ㉝ 超速提示：speed > speedLimitKmh（限速 > 0 时）
  ㉞ 0~60 绿 / 61~100 黄 / >100 红：已在 SevenSegment 里实现
  ㉟ 行程统计（本次最高速 / 平均速 / 行驶时长）：App 内自己累加即可，不占 BLE 带宽

 【解析正确性验证（本地已跑，不进 CI）】
   _ipa_analysis/verify_gauge_fields.py 把原小程序的 parseGaugeFrame 用 Node
   原样执行，与 Swift GaugeExtras 的位域实现逐项对照：
     9 组帧 = 4 组随机 33 字节完整帧 + 4/8/12/16 字节短帧 + 已知 88 km/h 样本
     共 212 个字段 → ALL PASS（完全一致）
   两处最容易抄错的地方已按原 JS 复刻：
     · AP 原始值 = 3 且上一次 AP = 0 时视为抖动并抑制为 0，否则会误报 AP 开启
       （Swift 侧由 TSLBLEManager 持续传入 previousAutoPilot）
     · 前/后电机功率为负数（能量回收）时，JS 的 Math.round = floor(x+0.5)，
       Swift 默认 .rounded() 是 awayFromZero，会差 1 kW → 已改用 .rounded(.down)

 ⚠️ 帧长度门槛（模块会发短帧或 33 字节完整帧，必须按长度判空）
   ≥4 字节：A1 的 ①②④⑤⑨、②（电量）、①（档位）等 head 位域
   ≥8 字节：A2 全部、⑰ 总里程
   ≥12 字节：㉒ 胎压
   ≥16 字节：㉔~㉗ 踏板 / 功率
   ≥33 字节：⑥⑦⑧⑯⑱⑲⑳㉑㉓㉘~㉛、单位 KM/H / MPH、手扶提醒
   GaugeExtras 用 Optional 表达「这帧没带」，界面要判空，不要用 0 冒充。

【B. 其它帧 · 需要新增请求与解析器（二期）】
--------------------------------------------------------------------------------
 B1 160 帧 · 设备信息（App 已会发，只是没解析回包）
   · 模块 ID / VIN / 硬件版本 hw_ver / 固件版本 / dat0 / esp
   · runtimeReady（运行固件就绪）、激活状态 auth_time
   · 用途：显示「已连到哪台模块 / 固件版本」，排查兼容性。不是行车数据。
 B2 208 帧 · batteryHub 电池包总览（需主动订阅）
   · 总电压 V、总电流 A、总功率 kW、车机 SOC %、实际 SOC %
   · 剩余里程 km、总充电量 / 总放电量 kWh、剩余能量 kWh、额定容量 kWh
   · 单体最高 / 最低电压、电池压差 mV、电池温度 ℃、正在预热
   · 另有「单体电压逐节」帧（parseCellFrame，最多 300 节）与 DCDC 帧
     （输入电压 / 输出电压 / 输出电流 / 输出功率）
   · 注意：208 是订阅制（batteryHub.use/release），要按需打开、用完释放，
     否则会一直占用 BLE 带宽，可能拖慢 176 帧，影响秒级实时。
 B3 192 帧 · canHub（订阅指定 CAN ID）
   · 按 cmd 列表订阅 CAN 报文，可选「全部」。属于调试 / 极客向，
     需要知道具体 CAN ID 才有意义，不建议进车机小组件。
 B4 168 / 169 帧 · 蓝牙密码
   · 168 = 校验结果（正确 / 错误 / 需要提交），169 = 修改密码的回包。
     只用于连接诊断，不做展示。
 B5 176 帧之外的告警类
   · 安全带未系 / 主驾安全带事件、TPMS 直读胎压传感器广播（小程序里
     pages/tpms 是 iPhone 直接监听特斯拉蓝牙 TPMS 广播，【不经过 TSL 模块】）
   · 若要复刻，需要另起一个 CBCentralManager 扫 TPMS 广播，属于独立功能。

【D. 明确做不到 / 不建议做的】
--------------------------------------------------------------------------------
   · 原 App 的小程序沙盒数据（wx.setStorageSync 的 gauge / tsl_settings 等）：
     独立 App 读不到，也不需要读。
   · CPTemplate 自定义全屏 CarPlay App：必须 Apple 授权 entitlement + 付费账号，
     自签做不了。当前方案走「systemSmall Widget + Live Activity 自动上 Dashboard」。
   · Widget Extension 自己连 BLE / 严格 1.5s 刷新：系统不允许，必须主 App 供数。
   · 在纯速度小组件里塞 10 个字段：systemSmall 只有约 158×158pt，
     驾驶时可读性会崩，也违背你定的「界面纯粹」。

【E. 建议的取舍（按开车时真正有用的程度排序）】
--------------------------------------------------------------------------------
 第一梯队（信息密度低、 glance 一眼可读，最推荐）
   档位 P/R/N/D · 电量 % · 剩余续航 km · 融合限速 km/h · AP 状态 ·
   转向灯箭头 · 门未关警告（只在异常时出现）
   → 适合做成「第二个 systemSmall」或 Live Activity 展开视图，
     纯速度小组件保持不动。

 第二梯队（数值型，适合 systemMedium / 主 App 副屏）
   四轮胎压 · 前/后/合计功率 · 电池温度 · 环境温度 · 加速踏板

 第三梯队（排查 / 极客向）
   总里程 · 海拔 · 四轮刹车温度 · 单体电压 · 鼓风机转速 · 蒸发器功率 ·
   灯光位 0xNN · 盲区等级 · 屏幕常亮 / 运动模式开关

 行车安全建议：车机上最多再加 2~3 个值；告警类用颜色/图标而不是文字；
 任何情况下都以车辆自身仪表为准。

【F. 接入方式（你看中哪几项后，我按这个改）】
--------------------------------------------------------------------------------
 方式 1：**另开一个 Widget**（推荐，不动纯速度那个）
   · 新增 Widget kind，例如 TSLStatusWidget，systemSmall 显示
     「档位 + 电量 + 续航」或「限速 + 超速警示」
   · 需要在 SpeedSnapshot / ContentState 里加字段 → 会触发
     scripts/verify_swift_calls.py 的逐一构造器顺序检查，所有调用点同步改。
   · 两个 target 的 Info.plist 与 project.yml 不用动（共用同一个 .appex，
     WidgetBundle 里多声明一个 Widget 即可）。

 方式 2：**Live Activity 展开视图 / 锁屏长条**
   · 大号速度保持主视觉，下方一行小字放 2~3 个字段
   · 数据不经过 App Group，自签最稳；车机 Dashboard 自动出现。
   · 同样要扩 ContentState。

 方式 3：**主 App 全屏仪表加副信息条**
   · 零数据契约改动：诊断页里的「最近一帧字段预览」已经把 GaugeExtras
     全部字段显示出来了，可以直接拿这段代码改成正式 UI。
   · 适合 AirPlay / AI Box 镜像投屏的源画面。

 方式 4：**诊断页直接确认数值**
   · 本轮已实现：主 App → 底部状态按钮 → 「连接诊断」→「最近一帧字段预览」
   · 先上车看一遍真实数值，再决定哪些字段值得做进小组件，避免白改。

 一句话：告诉我「要哪几个字段 + 放哪个界面（纯速度小组件保持不变 / 新开一个 /
 实时活动 / 主 App 副屏）」，我按对应的数据契约一次性改完并跑 CI 自检。
